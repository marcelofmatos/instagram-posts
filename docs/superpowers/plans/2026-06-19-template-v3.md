# Template v3 (fundo que ilustra a ideia) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar o template-v3 da arte do Instagram — o layout do v2 + um ícone temático (emoji) de fundo por lâmina, escolhido pelo claude (campo `bg`), com fallback por pilar.

**Architecture:** O `render.mjs` ganha um placeholder novo `{{BG_ICON}}` preenchido com `slide.bg` ou, se ausente, com um emoji de fallback por pilar (env `POST_PILLAR`). O `template-v3.html` é uma cópia do `template-v2.html` (que já traz o fundo cósmico da marca) + um elemento de ícone grande e apagado atrás do conteúdo. O `gerar-post.sh` passa a usar o v3 por default e exporta `POST_PILLAR`. O prompt instrui o claude a emitir `bg` por lâmina. Mudanças aditivas e retrocompatíveis (v1/v2 ignoram `{{BG_ICON}}`/`bg`).

**Tech Stack:** Node (render.mjs, sem libs novas), Chromium headless (já com `fonts-noto-color-emoji`), Bash, ImageMagick.

**Spec:** `docs/superpowers/specs/2026-06-19-template-v3-design.md`

**Neste repo (`instagram-posts`):**

Sem novos arquivos de teste unitário: `render.mjs` não é estruturado para import (roda no load), seguindo o padrão do repo os testes do renderizador são **smoke renders** (gera PNG, confere dimensão e diferença visual), como já foi feito no v2.

## Task 1: `render.mjs` — `{{BG_ICON}}` + fallback por pilar

Expected: imprime `✓ …/post-01.png` e `1080x1350`. Confirma que o v2 ignora o campo `bg` (retrocompatível) — baseline antes de mexer no render.

- [ ] **Step 2: Adicionar o mapa de fallback e o helper, logo antes do loop**

Em `renderer/render.mjs`, logo antes da linha `const posts = JSON.parse(readFileSync(postsPath, 'utf8'));`, inserir:

```js
// Ícone de fundo (v3): vem de p.bg; se ausente, cai no fallback por pilar (POST_PILLAR).
const PILLAR_ICON = { 'dor': '⚠️', 'antes-depois': '🔄', 'educacao': '💡', 'prova': '📊' };
const bgFor = p => p.bg || PILLAR_ICON[process.env.POST_PILLAR] || '';
```

- [ ] **Step 3: Adicionar a substituição de `{{BG_ICON}}` na cadeia de replaces**

Na construção de `const html = template…`, adicionar uma linha ao final da cadeia (depois do `.replace('{{CTA}}', …)`):

```js
    .replace('{{CTA}}', esc(p.cta || 'WhatsApp na bio →'))
    .replace('{{BG_ICON}}', esc(bgFor(p)));
```

(O `;` que estava no fim do `.replace('{{CTA}}', …)` passa para o fim do `.replace('{{BG_ICON}}', …)`.)

- [ ] **Step 4: Verificar sintaxe e retrocompatibilidade**

```bash
node --check renderer/render.mjs && echo "SINTAXE OK"
rm -rf /tmp/v3a && POST_TEMPLATE=template-v2.html node renderer/render.mjs /tmp/v3a.json /tmp/v3a
identify -format '%wx%h\n' /tmp/v3a/post-01.png
```
Expected: `SINTAXE OK`; o render v2 continua gerando `1080x1350` (o `.replace('{{BG_ICON}}', …)` é no-op no v2, que não tem o placeholder).


```css
    position:absolute;right:-30px;bottom:90px;z-index:0;
    font-size:560px;line-height:1;opacity:.13;pointer-events:none;
    filter:saturate(.85);
  }
```

Em `renderer/template-v3.html`, logo depois da linha `<div class="canvas">`, inserir:

- [ ] **Step 5: Provar que `bg` e o fallback por pilar injetam o ícone (3-way)**

```bash
echo '[{"num":1,"eyebrow":"DOR","title":"Mesmo titulo","body":"x","cta":"y"}]'           > /tmp/c_none.json
```
